4. What Is a Collection?

The Shopping Basket Analogy

A collection is a group of values or records stored together.

Single Record: Campaign Member A
Collection: [ Member A, Member B, Member C, Member D ]

The collection gives the Loop multiple records to work through.

Where Collections Come From

The most common source is a Get Records element configured to return All records.

Record-Triggered Flow
Get Related Records
Record Collection

5 & 6. Why Do We Need a Loop?

The Problem

Get Records may return many records. But Flow needs a way to process each record individually.

Collection = many records.
Current Item = one record being processed right now.

Sequential Execution

Collection: [ A, B, C, D ]

A → Process → B → Process →
C → Process → D → Process → Done!

7 & 8. Current Item & Loop Architecture

Current Item

Inside a Loop, Salesforce exposes a dynamic resource representing the record currently being processed.

  • Iteration 1 → Current Item = Record A
  • Iteration 2 → Current Item = Record B
  • Iteration 3 → Current Item = Record C

Current Item = the one record the Loop is handling now.

Loop Paths

Get Records → Collection
Loop Element
For Each Item:
Process Current Item → Next Item
After Last Item:
Exit Loop → Continue Flow

14. Hands-On #3: Bulk Update Related Assets

Business Requirement

When an Account is updated, find all Active Assets related to that Account, modify each Asset's Description, collect the modified records, and perform one bulk update after the Loop.

❌ Anti-Pattern: Update Inside Loop

Loop → Current Asset
Update Records
Next Item

Creates repeated database operations and is a poor scalable pattern.

✅ Best Practice: Collection Pattern

Loop → Modify Current Asset
Add Current Asset to Update Collection
After Last Item → Update Records

One collection of changes → one bulk update action.

16. Collection Types & Three Master Patterns

Collection Types

Retrieved Collection: Created from Get Records returning multiple records.

Record Collection Variable: A custom collection used to stage records for later bulk processing.

Current Item: A single record extracted from the collection during one Loop iteration.

Three Master Patterns

Hands-On 1: Trigger → Get → Loop → Current Item (Inspection)

Hands-On 2: Trigger → Get → Loop → Assignment → Update (Accumulation)

Hands-On 3: Trigger → Get → Loop → Modify → Collection → Bulk Update (Batch Processing)

17. Beginner Mistakes & Debugging Checklist

Top Mistakes

  • Using the wrong triggering object.
  • Referencing the trigger incorrectly instead of $Record.
  • Configuring Get Records to return only one record.
  • Confusing the collection with Current Item.
  • Forgetting to connect back to Next Item.
  • Placing Update Records inside the Loop.
  • Failing to initialize accumulation variables.

Debug Checklist

1. Did the Record-Triggered Flow fire?

2. Is $Record the expected record?

3. Did Get Records return the expected collection?

4. Is the Loop using the correct collection?

5. Is Current Item the expected record?

6. Is the Update Records action outside the Loop?

Golden Rule: The Loop is the iteration engine. It does not decide what happens to each record. Decision and Assignment provide the logic; the final DML action belongs outside the Loop.

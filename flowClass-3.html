4 & 5. What is a Variable & Why Do We Need It?

The Container Analogy

A variable is a named temporary container in memory.

[ Variable: TotalAmount ]
Initial State → ₦100,000
Add ₦20,000 → ₦120,000
Subtract ₦5,000 → ₦115,000

The container stays identical, but the stored value inside changes dynamically.

The Execution Pipeline

Initial Source Value
Store in Variable
Assignment (Modify / Calculate)
Use Value Downstream

6. Salesforce Fields vs. Flow Variables

Salesforce Record Field

Database Layer (Permanent)

  • Stored permanently inside the Salesforce database.
  • Belongs directly to a record (e.g., Contact.Email).
  • Visible on Page Layouts and in Reports.

Flow Variable

RAM / Execution Layer (Temporary)

  • Exists only while the Flow is actively executing.
  • Created in Flow Manager (e.g., TotalAmount).
  • Invisible on UI layouts until explicitly saved to a field.

Golden Rule: Field = Record Data in Database | Variable = Temporary Data in Flow Memory

14 & 15. Key Insight: Flow Staging vs Database

What Just Happened in Memory?

Contact Created → LoyaltyPoints = 100

Notice that the Contact record on Salesforce is NOT updated yet! The value of 100 currently lives purely inside the Flow's temporary memory. Assignment prepares information for downstream processing or collection operations.

35. Common Beginner Pitfalls

❌ Mistake 1 & 2

Confusing Variable with Field: Expecting a Flow variable to show up automatically on a Salesforce page layout.

Expecting Auto-Save: Assuming Assignment updates database records without an Update Records step.

❌ Mistake 3 & 4

Over-Creating Variables: Creating variables for static values that do not change or get re-used.

Hard-Coding Values: Writing fixed values like ₦500,000 instead of dynamic expressions like $Record.Amount * 0.10.

36. Debugging Assignment Checklist

  1. Does the target variable resource exist in the Flow Manager?
  2. Is the variable's Data Type correct (Text, Number, Currency, Boolean)?
  3. Is the Assignment element placed on the correct execution path?
  4. Are you using the correct Operator (Equals vs. Add vs. Subtract)?
  5. Is the variable referenced downstream in an Action or Update element?
  6. If database persistent, did you execute an Update Records step?
